# Mark 0.3

一个面向 macOS 的轻量 Markdown 桌面编辑器。Markdown 原文是唯一数据源，CodeMirror 的语法树装饰负责即时渲染，格式显示不会重新序列化文档。

## 安装与运行

需要 Node.js 22.12 或更高版本（含 npm），在包含 `package.json` 的项目根目录执行命令。当前交付并验证的平台为 macOS Apple Silicon / Node.js 24；Windows 可按下文从源码运行，尚未完成 Windows 实机验收。

### macOS

```sh
npm ci
npm run dev
```

开发模式会启动 Vite 和 Electron 桌面窗口。修改渲染层代码可即时更新；修改主进程或 preload 后需要重启开发命令。

已有源码构建后，也可以不启动开发服务器，直接运行：

```sh
npm run build
npm start
```

打包本地应用：

```sh
npm run package
```

构建结果位于 `release/mac-arm64/Mark.app`（Apple Silicon）或 `release/mac/Mark.app`（Intel）。目前只验证了 Apple Silicon 版本。应用未签名、未公证，用于本地试用；没有自动更新。

### Windows：从源码运行

1. 安装 Windows 版 Node.js 22.12 或更高版本，安装时包含 npm 并加入 PATH，然后重新打开 PowerShell 或命令提示符。
2. 将项目源码放到本地目录，例如 `C:\Projects\mark`。不要复制 macOS 下的 `node_modules`；依赖和 Electron 必须在 Windows 上重新安装。
3. 在 PowerShell 中进入实际项目目录，安装锁定版本的依赖与 Windows Electron，再启动：

```powershell
cd C:\Projects\mark
node --version
npm --version
npm ci
npx install-electron --no
npm run dev
```

首次安装需要网络连接，以下载 npm 依赖和对应平台的 Electron。`npm run dev` 会打开桌面编辑器；保持终端运行，退出应用后开发服务器随之关闭。文件操作需在 Electron 窗口中使用，单独打开浏览器里的开发地址不能代替桌面运行。

日常使用也可以先构建，再直接启动，无需运行 Vite 开发服务器：

```powershell
npm run build
npm start
```

构建只生成 `dist` 和 `dist-electron`，仍需项目依赖及 Node.js 才能通过 `npm start` 启动。当前未提供 Windows 安装包或独立 `.exe`；`npm run package` 明确指定了 `--mac`，不是 Windows 打包命令。`npm run icons` 使用 macOS 的 `iconutil`，也不要在 Windows 上执行；从源码运行无需重新生成图标。

Windows 操作说明：

- 新建／打开／保存：`Ctrl+N`、`Ctrl+O`、`Ctrl+S`；另存为：`Ctrl+Shift+S`。
- 加粗／斜体／撤销：`Ctrl+B`、`Ctrl+I`、`Ctrl+Z`；重做可用 `Ctrl+Shift+Z`。
- 源码切换：`Ctrl+/`；插入图片：`Ctrl+Shift+I`；导出 PDF：`Ctrl+Shift+E`。
- 链接用 `Ctrl+点击` 在外部浏览器打开；正文 `Enter` 换段、`Shift+Enter` 换行与 macOS 相同。
- 界面部分提示仍使用 macOS 的 `⌘` 和 Finder 文案；Windows 对应 Ctrl 和文件资源管理器。窗口样式、原生菜单、文件覆盖、图片路径及 PDF 字体排版尚需 Windows 实机回归。

常见启动问题：

- PowerShell 提示 `npm.ps1` 无法运行：使用 `npm.cmd` 替代 `npm`，`npx.cmd` 替代 `npx`，或改用命令提示符；不需要修改系统执行策略。
- 找不到 `node` 或 `npm`：确认已安装并加入 PATH，然后重新打开终端。
- Electron 下载失败或缺少可执行文件：检查网络连接后重新执行 `npx install-electron --no`。
- 提示 5173 端口被占用：关闭之前运行的 Mark 开发进程，再执行 `npm run dev`；也可使用 `npm run build` 和 `npm start`。

### 开发检查

```sh
npm test              # 内核、文件、图片资源及导出相关单元测试
npm run build         # TypeScript 类型检查与应用构建
npm run test:desktop  # 真实 Electron 窗口交互测试，需要桌面会话
```

## 编辑功能

- 单窗口单文档，中文界面，暖纸／纸白／石墨／午夜蓝四套主题。
- 标题、粗体、斜体、删除线、引用、列表、行内代码、围栏代码块、链接和分隔线。
- 当前段落显示 Markdown 标记；代码块整体展开；跨段选择展开涉及的段落。列表项独立展开。
- 即时渲染和源码模式共享文本、选区及撤销历史；打开新文档会重置历史。
- 正文 Enter 换段（插入空行），Shift+Enter 换行（插入两个空格与换行，保存为 Markdown 硬换行）。列表 Enter 续项，空项 Enter 退出；代码、HTML 和公式块中 Enter 普通换行；源码模式保持常规换行。Tab / Shift+Tab 缩进。
- HTML 常用排版标签、上下标、颜色、对齐、表格和链接预览；点击渲染内容回到源码。
- KaTeX 离线公式排版：行内 `$...$` / `\(...\)`；行间 `$$...$$` / `\[...\]`，支持多行、分式、积分和 aligned 等环境。
- 文本按纯文本粘贴，剪贴板图片自动导入；中文输入支持，⌘B 加粗、⌘I 斜体、⌘Z 撤销、⌘⇧Z 重做。
- ⌘N 新建、⌘O 打开、⌘S 保存、⌘⇧S 另存为、⌘/ 切换源码。
- 手动保存；离开未保存文档时可保存、放弃或取消。
- UTF-8 `.md` / `.markdown` / `.txt`，保留 BOM 及文件的主要换行风格；新文件使用 LF、不带 BOM。混合换行文件保存时统一为首次检测到的换行风格。不接受无效 UTF-8，避免悄悄损坏内容。
- 同目录临时文件写入并替换，保存前比较磁盘内容哈希；外部变更或删除时选择覆盖、另存为或取消。
- ⌘点击链接在外部浏览器打开，仅允许 HTTP、HTTPS 和 mailto。

浏览器开发预览可以验证编辑体验，文件操作仅在桌面应用中开放。

## 结构

- `src/editor`：独立编辑核心，基于 Markdown 语法树生成视口内的显示装饰。输入法组合输入期间暂停隐藏语法标记。
- `src/main.ts`：界面、文档操作和状态同步。
- `electron/files.ts`：UTF-8 读写、格式保持、原子替换和冲突检测。
- `electron/session.ts`：文档生命周期与可测试的对话框决策流程。
- `electron/main.ts` / `preload.ts`：原生窗口、菜单和受限 IPC。渲染层启用 sandbox、contextIsolation，禁用 Node.js。

HTML 在受限标签和样式白名单内渲染，脚本、事件属性、iframe、表单、外部资源和页面定位样式会被过滤；源文件始终保留原始内容。HTML 链接仅通过 ⌘点击显式外部打开。KaTeX 禁用 trust，错误公式显示错误提示，未闭合公式保持源码。文件操作期间暂时禁止编辑，以防保存或切换文档时丢失并发输入。保存失败不会更新基线；操作取消不会清空当前内容。

## 验证与限制

单元测试覆盖格式/BOM/换行保留、中文路径、无效编码、原子写入失败清理、保存取消、离开保护、外部冲突、打开失败、语法装饰、活动段落、嵌套列表、未闭合语法、模式切换和撤销历史。

桌面测试使用真实 Electron 窗口与临时文件，替换原生文件对话框的返回值以便自动化；检查新建、保存、重开、源码模式、撤销重做、取消离开以及约 1 MB 文档的加载/编辑/滚动。截图位于 `test-results/`。原生输入法候选词窗口和不同第三方输入法仍需要人工回归，模拟组合输入不能替代这些检查。已通过 Chromium IME 协议模拟中文组合输入及方向键/删除测试。

当前版本没有 Markdown 表格编辑、图表、大纲、查找替换、文件树、多标签、云同步、插件或崩溃草稿恢复。不支持的语法仍作为原文保存。围栏代码块目前显示等宽背景，不提供语言专属高亮。Windows 提供源码启动说明，但尚未实机验证；Linux 和其他 Mac 架构也尚未验证。

冲突检测在写入前执行；无法完全消除其他程序在检测与原子替换之间同时写入的竞争窗口。应用不会自动覆盖外部修改。

当前 0.3.0 本机验收：71 项自动测试通过，Electron 桌面测试无渲染错误；约 1.1 MB 文档的加载、编辑和滚动已回归。图标更新后的单次测量：加载约 41 ms，编辑与滚动约 138 ms；这些数据不是跨设备性能保证。


## HTML / LaTeX 示例

```markdown
这是 $E=mc^2$，还有 H<sub>2</sub>O。

<div style="text-align:center;color:#47795e"><b>居中标题</b><br>下一行</div>

$$
\int_0^1 x^2\,dx = \frac{1}{3}
$$
```

编辑段落时显示原文，光标离开后显示 HTML / 数学排版。点击公式或 HTML 预览可回到源码编辑，源码切换与保存不会转换或重写公式。代码区中的 HTML / 公式保持字面文本。HTML 内支持本地图片，不提供脚本、远程图片和任意 CSS 支持；公式支持范围遵循 KaTeX，而非完整 LaTeX 文档编译。

HTML / LaTeX 桌面回归覆盖 Enter / Shift+Enter、HTML 预览、四种公式定界符、公式点击回到源码、全选展开、保存原文往返与中文组合输入。


## 0.3 图片管理

通过工具栏“图片”（⌘⇧I）、拖放图片文件或粘贴剪贴板图片插入。支持 PNG、JPEG、WebP、GIF；单张限制 25 MB，每次最多 50 张。首次插图先保存文档，随后复制到同目录的 `文档名.assets` 文件夹并插入相对链接。同内容图片复用资源；同名不同内容不会覆盖。

图片插入支持撤销；撤销只移除正文引用，不立即删除资源。点击图片显示可编辑的 Markdown 源码。图片管理面板可查看缩略图、大小、引用/缺失状态，并在 Finder 定位；只有同时不被当前内容和已保存内容引用的托管图片才可清理，清理前列出文件并确认，随后移入废纸篓。撤销编辑可能重新引用已经清理的图片，此时可从废纸篓恢复。

应用内“重命名”同步修改文档、对应图片目录和图片链接；“另存为”复制资源并保留原件，其他本地图片引用自动重新计算相对路径。目标图片目录已存在时会停止操作，不合并或覆盖。应用不跟踪 Finder 中的外部改名；手动迁移时请把 `.md` 与 `.assets` 目录一起移动。资源目录不支持符号链接。正常运行中的失败会回滚；文件与目录无法组成跨文件系统原子事务，操作过程中强制断电仍可能留下 `.backup` / `.tmp` 恢复文件。

仅加载当前文档引用的本地图片及其受管理图片目录，不自动下载网络图片。Markdown 直接图片、引用式图片、HTML `<img>` 均可预览；找不到文件时显示缺失占位。代码及公式中的图片示例不会作为真实引用改写。

## PDF 导出

使用工具栏“导出 PDF”或 ⌘⇧E，导出当前编辑内容，包括尚未保存的修改。导出不会自动保存 Markdown 或清除未保存标记。

- 填写标题、作者、主题描述和关键词，写入 PDF 文件属性；可另选在正文前显示标题、作者及日期。作者默认空白，文档信息不会成为下个文档的默认值。
- 页眉、页脚分别启用，每项分左中右三栏。支持 `{title}`、`{author}`、`{date}`、`{page}`、`{pages}`；先聚焦输入栏，再点击变量按钮插入。过长的页眉页脚会提示缩短。
- A4 / A5 / Letter，横向 / 纵向，10–40 mm 页边距；启用页眉或页脚时，对应边距至少 18 mm。
- 独立选择简洁白纸／书籍／学术排版。深色编辑主题不会让 PDF 变为深底。字体、公式和本地图片随应用离线提供或使用系统中文字体。
- 预览使用系统默认 PDF 应用打开临时文件；预览文件保留至 Mark 正常退出。正式导出成功后可打开或在 Finder 中定位。
- 缺失图片先列出问题，可返回修复或用占位继续。保存取消不写文件，导出失败不会替换已有 PDF。

页眉页脚、纸张和排版偏好保存在当前用户的应用配置目录；只记住页面设置，不保存标题、作者、描述、关键词。常规换行、HTML 过滤和 LaTeX 规则与编辑器共用。

## 主题

右上角主题菜单即时切换整个界面，包括弹窗、源码颜色、选区、图片和公式。重启自动恢复选择，不改写文档、不重置撤销历史。HTML 中用户明确设置的颜色仍按原样保留。

## 新增开发模块与验收

- `src/document`：图片引用语法解析、编辑与导出共用的 Markdown / HTML / KaTeX 渲染。
- `electron/assets.ts`：资源导入、去重、引用查询、文件与资源联动。
- `electron/pdf.ts` / `src/print.ts`：隐藏打印窗口、字体与图片就绪检查、页眉页脚、PDF 元数据及原子写入。
- `src/settings.ts` / `electron/preferences.ts`：主题与 PDF 页面偏好校验和持久化。

桌面验收对文件对话框、清理确认、废纸篓调用使用临时文件及受控返回值；不会操作用户文档。三种 PDF 排版各生成 5 页样例，使用 PDF 解析验证中文作者、标题、关键词及页码，再逐页渲染检查图片、公式、字体、页眉页脚和分页。测试 PDF、截图位于忽略的 `test-results/`。

0.3.0 验收：71 项自动测试通过。真实 Electron 测试覆盖图片选取、粘贴、拖放、撤销、去重、重命名、另存为、清理确认、PDF 文件属性与页码、导出取消保护、主题重启记忆，以及原有中文输入和大文档编辑。

## 应用图标

图标采用暖白纸面、深绿矢量 M 和棕金色笔迹，与默认暖纸主题保持一致。母版为 `build/icons/mark.svg`（1024 × 1024，字形为路径，不依赖字体）；对应 PNG、多尺寸 `mark.iconset`、`mark.icns` 和浅深背景预览均在同目录。

在 macOS 上安装依赖后执行 `npm run icons`，通过 Electron 的 Chromium 画布生成透明 PNG，再由系统 `iconutil` 合成 ICNS。包括 16、32、128、256、512 点的 1× / 2× 资源；小尺寸移除纸面细线，16 / 32 像素进一步加粗 M 并移除棕金色点缀。图标保留传统 macOS 图标的透明外边距，不随编辑器主题改变。

执行 `npm run package` 将图标装入 `release/mac-arm64/Mark.app`。重新生成图标后需重新打包；若 Dock 仍显示旧图标，先退出旧应用，再打开新打包版本。
